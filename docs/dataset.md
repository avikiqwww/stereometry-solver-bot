# Часть I. Постановка

## 1. Что за проект и зачем нужен фильтр

Я делаю Telegram-бота, который решает задачи по **стереометрии** (геометрии в пространстве: пирамиды, призмы, шары, сечения). Бот работает в два шага:

1. **Фильтр.** Пришло сообщение. Это задача по стереометрии или нет?
2. **Решатель.** Если да, задача передаётся большой языковой модели (LLM), которая её решает.

Фильтр нужен по трём причинам:

- **Экономия.** Запрос к LLM стоит времени и ресурсов, незачем тратить их на «привет, как дела».
- **Защита.** Решатель, которому дали алгебру или болтовню, начнёт сочинять «решение стереометрической задачи» из ничего.
- **Качество.** Чем точнее фильтр, тем меньше мусора доходит до решателя.

Этот документ описывает **первый этап**: построить обучающие данные для фильтра и подготовить текст так, чтобы на нём можно было обучить классификатор (метод опорных векторов, SVM). Сам бот и решатель в документ не входят.

### Какие подходы к фильтру рассматривались

| подход | идея | чем плох или хорош |
|---|---|---|
| регулярные выражения | искать слова «пирамида», «объём» и т. д. | без обучения, но каждое новое слово надо вносить руками |
| **TF-IDF + линейная модель** | превратить текст в числа и обучить простую модель | быстро, объяснимо, нужен небольшой датасет |
| эмбеддинги + классификатор | готовая нейросеть превращает текст в вектор | понимает синонимы, но тяжелее |
| дообучение BERT | нейросеть подстраивается под задачу | лучшее качество, нужен GPU и больше времени |
| LLM как классификатор (zero-shot) | спросить LLM «это стереометрия?» | не нужен датасет для обучения, но дорого и медленно |

Я начинаю с **TF-IDF + SVM**: это классика, которая учит понимать текст «под капотом», и она даёт честную точку отсчёта, с которой потом сравниваются остальные методы.

## 2. Что такое классификация (теория)

**Простыми словами.** Классификация - это когда мы показываем компьютеру много примеров с правильными ответами («это стереометрия», «это нет»), а он учится сам находить правило, по которому можно угадывать ответ для новых примеров. Это как репетитор, который даёт ученику сборник с ответами, а потом проверяет на новых задачах.

**Чуть строже.** Задача **обучения с учителем** (supervised learning). Есть набор объектов $x_i$ (у нас - тексты) и правильные ответы $y_i$ (**метки**, у нас $y_i \in \lbrace 0, 1 \rbrace$: 1 - стереометрия, 0 - нет). Вместе они образуют **датасет**:

$$
D = \lbrace (x_i, y_i) \rbrace_{i=1}^{n}.
$$

Нужно найти функцию $f$, которая по тексту предсказывает метку:

$$
f : \mathcal{X} \to \lbrace 0, 1 \rbrace, \qquad \hat{y} = f(x).
$$

Хорошая $f$ - это не та, которая запомнила обучающие примеры, а та, которая правильно отвечает на **новых** текстах. Это свойство называют **обобщающей способностью**. Если модель идеально отвечает на обучающих примерах и плохо на новых, говорят о **переобучении**.

### Обучающая и тестовая выборки

Нельзя проверять модель на тех же примерах, на которых она училась: это как дать ученику на экзамене те же задачи, которые он решал дома. Поэтому данные делят:

- **обучающая выборка (train)** - по ней модель подбирает параметры;
- **тестовая выборка (test)** - по ней мы проверяем качество, модель её не видела.

Как именно делить данные и что при этом может пойти не так, разбирается отдельно, в документе про оценку модели.

### Почему данные важнее модели

В машинном обучении есть правило «**мусор на входе - мусор на выходе**». Даже самая умная модель выучит то, чему её учат. Если в данных есть случайная закономерность, не связанная с задачей (например, «задачи из книги A всегда стереометрия»), модель выучит и её, и метрики на таких данных будут красивыми, но бесполезными. Именно этому посвящена большая часть проекта: мы строили датасет и проверяли, чему на нём учится модель.

# Часть II. Датасет

## 3. Из чего состоит датасет и почему именно так

### Классы и пропорции

| класс | что это | доля | строк (итог) |
|---|---|---|---|
| **1. Позитив** | задачи по стереометрии | 40% | 800 |
| **0. Сложный негатив** | планиметрия и алгебра | 40% | 782 |
| **0. Лёгкий негатив** | приветствия, болтовня, оффтоп | 20% | 400 |
| | | итого | **1982** |

Планировалось 2000 строк (800 / 800 / 400), получилось 1982: после сборки удаляются дубликаты.

Формально пропорции задаются так: при общем размере $N = 2000$ берём $n_+ = 0{,}4N = 800$, $n_{\text{hard}} = 0{,}4N = 800$, $n_{\text{easy}} = 0{,}2N = 400$.

### Зачем нужны негативы, и почему два вида

**Простыми словами.** Модели недостаточно показать «вот стереометрия». Ей нужно показать и «вот не она», причём именно то, что на неё похоже. Если ученик учил только «пирамида - стереометрия», а «треугольник - не стереометрия» ему не показали, то на задаче про треугольник он начнёт ошибаться.

- **Сложные негативы** (hard negatives) - планиметрия и алгебра. В них встречаются те же слова, что и в стереометрии: «найдите», «площадь», «угол», «треугольник», «равен». Если их не дать, модель повысит вес слов вроде «площадь» и начнёт называть стереометрией любую геометрию. Это самые полезные примеры: они определяют, где модель проводит границу.
- **Лёгкие негативы** - приветствия, вопросы не по теме («какая завтра погода?»). Их отличить легко, они нужны, чтобы бот не реагировал на болтовню.

На данных это подтвердилось. Доля правильных ответов пробной модели (линейный SVM, 5-кратная проверка) по группам:

| группа | строк | правильных ответов |
|---|---|---|
| алгебра | 320 | 0.975 |
| планиметрия | 462 | **0.948** |
| мусор | 400 | **1.000** |
| стереометрия | 800 | 0.959 |

Мусор модель всегда угадывает правильно (он лёгкий), а планиметрия - самое трудное место.

### Откуда взялись пропорции 40 / 40 / 20

Честно: эти пропорции я выбрал как **рабочую эвристику** в плане проекта, их не выводили из теории и не подбирали экспериментом. Логика такая:

- позитивов должно быть достаточно, чтобы выучить класс (у нас их ровно столько, сколько удалось собрать: 800);
- сложных негативов столько же, потому что именно на них модель ошибается;
- лёгких негативов меньше, потому что они лёгкие: много таких примеров не нужно, а метрика от них только надувается (общая accuracy 0.967 с мусором и 0.959 без него).

Итоговое соотношение классов 40% к 60% - не 50 на 50, но достаточно близко, чтобы показатель accuracy имел смысл.

**Ограничение.** Реальная доля стереометрии среди сообщений пользователей неизвестна. Если в боте стереометрия составляет 5% сообщений, а в датасете 40%, то порог и вероятности придётся пересматривать (это называется **сдвигом априорных вероятностей**).

**Что оказалось важнее пропорций.** Не соотношение классов, а **состав** сложных негативов: формат записи, стиль (доказательства против вычислений). Когда мы это поняли, мы поменяли распределение внутри сложных негативов (планиметрия 60% и алгебра 40% вместо 50 на 50), но общую долю 40% не трогали.

### Дополнительные поля

В рабочем датасете у строки есть:

- `text` - текст, `label` - метка (то, что видит модель);
- `category` - тип (stereometry, planimetry, algebra, junk и подтипы мусора);
- `source` - из какого источника строка.

`category` и `source` **в модель не идут**. Они нужны мне для анализа: балансировать источники, искать утечки и проверять модель на источнике, которого она не видела. В финальном файле для обучения останутся только `text` и `label`.

## 5. Как данные собирались (парсинг)

**Простыми словами.** **Парсинг** - это когда программа сама открывает страницу или файл и вытаскивает из него нужные куски текста, вместо того чтобы человек копировал руками.

Нужные базовые понятия:

- **HTML** - текст страницы с метками (**тегами**), которые говорят браузеру, где заголовок, где абзац. Из него легко достать нужный блок.
- **POST и GET** - два способа запросить страницу. GET - просто «дай страницу», POST - «вот мои параметры, дай страницу по ним».
- **Кодировка** - таблица, по которой байты превращаются в буквы. Если угадать её неверно, вместо русского текста будет каша. Сайты ФИПИ отдают текст в `windows-1251`, а не в привычной `utf-8`.
- **TLS-сертификат** - «паспорт сайта», по которому браузер убеждается, что говорит с настоящим сайтом. Паспорт подписывается цепочкой организаций. ФИПИ не присылает одно из звеньев этой цепочки.
- **PDF с текстовым слоем и скан.** В PDF с текстовым слоем символы хранятся как текст, их можно достать программой. Скан - это просто картинка страницы, для него нужно распознавание текста (OCR).

### 5.1. ФИПИ (ЕГЭ и ОГЭ)

Сайты `ege.fipi.ru/bank` и `oge.fipi.ru/bank` - официальный банк заданий. Раздел `robots.txt` их не запрещает (это файл, где сайт сообщает, что роботам читать нельзя).

Что выяснилось по ходу, и как это учтено:

- Страницы отдаются готовым HTML, браузер не нужен. Список заданий возвращает POST-запрос с номером страницы, около 10 заданий на страницу (ЕГЭ профильный: ~1148 заданий, ~115 страниц; ОГЭ: ~3884 задания, ~389 страниц).
- Фильтр по теме на стороне сайта работал ненадёжно, поэтому я скачиваю всё и отбираю по тегу **КЭС** (кодификатор элементов содержания) у каждого задания. У одного задания бывает несколько КЭС, учитываются все.
  - ЕГЭ: 7.1 - планиметрия (негатив), 7.2-7.4 - стереометрия (позитив).
  - ОГЭ: 7.1-7.6 - геометрия (в 9 классе стереометрии нет, значит это планиметрия), разделы 2 и 3 - алгебра.
- **Двойные теги.** Одно задание может иметь несколько КЭС сразу, например «7.1 Фигуры на плоскости» и «7.3 Многогранники». Такое задание попадает **и в файл планиметрии, и в файл стереометрии**. В сырой планиметрии ЕГЭ (140 заданий) таких оказалось 18, и у всех в тексте есть слова из трёхмерной геометрии. Мой парсер этого не отсекает. Защитой служит итоговая дедупликация при сборке (раздел 8): совпавшие тексты удаляются из негативов. Я проверил результат: среди негативов-планиметрии ни одной задачи со словами из 3D не осталось (6 строк алгебры со словами 3D - это текстовые задачи про силу Архимеда и покупки, они к стереометрии не относятся). **Правильное исправление парсера** (не делал): не класть задание в планиметрию, если у него есть любой тег стереометрии.
- Кодировка ответа `windows-1251` указывается явно.
- Сайт не присылает промежуточный сертификат, браузеры сами его докачивают, а Python-библиотека `requests` нет. Решение: нужный сертификат лежит в репозитории и добавляется к стандартному набору (`certifi`).
- Сбои сети: каждая страница запрашивается до 3 раз с растущей паузой. Если не получилось, сбор останавливается, а то, что уже собрано, сохраняется (раньше при таймауте терялось 230 заданий).
- Портится одно слово: «бо́льший» (с ударением) иногда превращается в «бо�ьш» с символом ошибки U+FFFD. Это встретилось в 12-19 заданиях всегда в одном виде, поэтому слово чинится точечно регулярным выражением, а не выбрасывается.
- Задания-обрубки: у части заданий текст не извлёкся (например, остался один «Решите неравенство»). Они отбрасываются: если текст короче 15 символов, или нет ни цифр, ни знаков, ни слова «докажите». Обрубки составляют около 21% алгебры ОГЭ.

### 5.2. Прасолов, «Задачи по стереометрии»

PDF с текстовым слоем. Сложности:

- **Какая библиотека читает PDF.** `pdfplumber` разъезжается на индексах (`A1` превращается в `A` и `1` в разных строках). `PyMuPDF` извлекает в правильном порядке, взят он.
- Книга чередует главы «Условия задач» и «Решения». Страницы, которые начинаются со слова «Решения», пропускаются.
- Задача отделяется по номеру вида `2.9.` (номер главы, точка, номер задачи).
- **Переносы слов** («ле-жащей» на границе строк) склеиваются обратно.
- Хвосты колонтитулов («Решения», «Условия задач 5») удаляются.
- Фильтры самодостаточности: длина 20-400 символов; нет «рис.»; нет «см. также задач»; нет колонтитула «N Глава M.»; нет слова «постройте» (задачи на построение текстом не решить); есть слово-маркер задачи («докажите», «найдите» и т. д.).
- Найдено 582 задачи.
- **Возможная проблема, которую стоит проверить:** в книге по планиметрии у задач повышенной сложности в номере стоит звёздочка (`5.62*.`), и мой первый парсер планиметрии пропускал их (терялась половина книги). Парсер стереометрии использует похожий шаблон номера, и я не проверял, есть ли такие задачи в стереометрической книге. Если есть, часть задач пропущена.

### 5.3. Захаров

PDF, задачи пронумерованы «Задача 1.», «Задача 2.» (нумерация повторяется в каждом из 8 уроков), поэтому текст режется по этому маркеру. Дальше:

- удаляется повторяющаяся подпись автора внизу страницы;
- удаляется хвост «Домашнее задание»;
- отбрасываются «развалившиеся» тексты (больше 25% однобуквенных слов: так PDF превращает формулы решений в мешанину);
- отбрасываются обрывки вида «равно √ .», где число под корнем не извлеклось;
- требуется хотя бы одно слово из трёхмерной геометрии (иначе это кусок 2D-примера из теории);
- найдено 133 задачи.

### 5.4. Прасолов, «Задачи по планиметрии»

PDF на 636 страниц, около 2000 задач. Здесь потребовалось больше работы:

- В конце **каждой** из 31 главы идёт раздел «Решения», и он начинается не всегда с новой страницы. Поэтому пришлось идти по строкам и вести состояние («сейчас читаю условия» или «сейчас решения»): строка «ГЛАВА N» включает условия, строка «Решения» включает решения.

## 6. Фильтры качества

Фильтры работают на этапе парсинга, чтобы в датасет не попадал мусор.

| фильтр | что отсекает | зачем |
|---|---|---|
| картинка / «рисунок» | задачи, зависящие от чертежа | текстовый фильтр не может их понять |
| длина | слишком короткие обрывки и слишком длинные куски | обрывок - это не условие |
| «построение» | «Постройте…» | LLM-решатель не ответит текстом, нужен чертёж |
| развалившаяся формула | много одиночных символов (доля обрывков выше порога) | PDF превращает дроби и степени в кашу |
| слова из 3D в негативах | планиметрия, где вдруг есть «куб» или «пирамида» | иначе метка «не стереометрия» окажется ошибочной |
| слово-маркер задачи | тексты без «найдите», «докажите», «вычислите» и т. п. | отсекает куски решений |
| дубликаты | один и тот же текст | искажают пропорции и метрики |

## 7. Лёгкие негативы: генератор мусора

Реального источника «случайные сообщения боту» не существует, поэтому такие примеры генерируются из шаблонов (`parser/junk_generator.py`).

Составные части:

- приветствия (10), реплики «как дела?» (10), посторонние вопросы (20), вопросы про математику, которые не задачи («Что такое пирамида?» - таких 10), вопросы про бота (10), жалобы и шум (16);
- сочетания «приветствие + реплика» (10 x 10 = 100 плюс 10 одиночных приветствий);
- если шаблонов не хватает, добавляются все сочетания «приветствие + вопрос» (10 приветствий x 40 вопросов = 400).

Итог: 166 готовых шаблонов + 234 сочетания = **400** строк, все разные. Важная деталь: фразы вроде «Что такое пирамида?» **намеренно** относятся к негативам. Бот не должен решать вопрос про определение пирамиды как задачу.

## 8. Сборка итогового датасета

Скрипт `parser/assemble_dataset.py` собирает всё в один файл `data/processed/filter_dataset.jsonl` (формат: одна JSON-строка на пример).

Шаги:

1. Взять пул позитивов (три источника), удалить дубликаты, случайно выбрать 800.
2. Собрать сложные негативы. Квота 800: **планиметрия 60% (480)** и **алгебра 40% (320)**.
   - В планиметрию берутся **все** доказательства ФИПИ (в сырых данных их 151);
   - добавляется 150 доказательств Прасолова-планиметрии;
   - остаток квоты добирается обычными (вычислительными) задачами ФИПИ.
3. Взять 400 лёгких негативов из генератора.
4. Собрать всё в одну таблицу, ещё раз удалить дубликаты, перемешать, записать.

Доказательством считается текст, где есть корень «докаж» или «обоснуй». Планиметрии в датасете 462, а не 480: итоговая дедупликация удалила 18 строк. 17 из них - задачи ФИПИ ЕГЭ, которые на самом деле стереометрические (у них двойной тег КЭС, см. [5.1](#51-фипи-егэ-и-огэ)) и совпали с позитивами, а ещё одна - дубликат внутри Прасолова-планиметрии. Дедупликация идёт **в порядке «позитивы, потом негативы»**, поэтому при совпадении текста остаётся позитивная копия, и стереометрическая задача с меткой «не стереометрия» в датасете не оказывается.

### Три версии датасета

| версия | строк | позитив / сложный / мусор | доказательства |
|---|---|---|---|
| v1 (первая сборка) | 1995 | 800 / 795 / 400 | позитивы: 501 из 800 (63%); негативы: 39 из 1195 (3%) |
| v2 (все доказательства ФИПИ в негативы) | 1983 | 800 / 783 / 400 | негативы: 135 из 1183 (11%) |
| v3 (+ Прасолов-планиметрия, квоты 60/40) | 1982 | 800 / 782 / 400 | позитивы: 501 из 800 (63%); планиметрия: 284 из 462 (61%); алгебра: 0 из 320 |

**Зачем понадобились v2 и v3.** В v1 доля задач на доказательство («Докажите, что…») сильно отличалась между классами: среди позитивов их 63% (501 из 800), среди негативов только 3% (39 из 1195). Такая разница - лазейка: по слову «докажите» можно угадывать класс, не понимая тему. Поэтому в v2 в негативы добавили все доказательства ФИПИ по планиметрии (151 штука), а в v3 ещё 150 доказательств из книги Прасолова по планиметрии и поменяли квоты «планиметрия / алгебра» на 60 / 40. После этого доля доказательств среди планиметрических негативов (61%) почти сравнялась с долей среди позитивов (63%).

## 9. Контроль качества датасета

Читать 2000 строк глазами долго, поэтому я написал скрипт `parser/quality_check.py`, который помечает подозрительные строки. Все проверки, кроме последней, дёшевы и не требуют машинного обучения.

| проверка | что ищет |
|---|---|
| длина | строки короче 15 или длиннее 500 символов (для болтовни короткие допустимы) |
| развалившаяся формула | доля однобуквенных «слов» больше 0.25 |
| оборванный символ | корень `√` перед знаком препинания или концом строки |
| утечка служебных слов | «рис.», «Решения», «Домашнее задание», «Глава N» |
| позитив без цифр | число должно быть, кроме задач на «докажите», «существует ли» и т. п. |
| позитив без терминов 3D | текст мог попасть не в тот класс |
| почти-дубликаты | один шаблон, разные числа |
| **перплексия** | насколько текст «удивляет» языковую модель |

### Почти-дубликаты

Задачи вида «Ребро куба равно 5. Найдите объём» и «Ребро куба равно 12. Найдите объём» - один шаблон. Чтобы их найти, все числа заменяются на символ `#`, и совпавшие строки объединяются в группу. Групп с более чем тремя повторами было **58** в первой версии и **48** в текущей. Это важно, когда данные делят на обучающую и тестовую части: если одну задачу отдать в обучение, а её почти-копию в тест, модель «подсмотрит», и оценка завысится.

### Перплексия

**Простыми словами.** Готовая языковая модель читает текст и оценивает, насколько он похож на нормальный русский язык. Связный текст она находит «ожидаемым», а мешанину символов («cos a 2 cos b 2…») - «удивительной». Строки, которые модель сильнее всего удивляют, подозрительны.

**Чуть строже.** Для текста из токенов $w_1, \dots, w_N$ перплексия языковой модели равна

$$
\mathrm{PPL} = \exp\left(-\frac{1}{N}\sum_{i=1}^{N}\log p(w_i \mid w_{<i})\right).
$$

Чем выше значение, тем менее «естественным» модель считает текст. Я использую русскую модель `rugpt3small` (локально, без запросов к внешним сервисам) и отмечаю верхние 3% по перплексии. Таким способом чистят большие текстовые корпуса.

### Что нашли проверки

- задания-обрубки у ФИПИ (около 21% алгебры ОГЭ) и зависимые от рисунка;
- испорченное слово «бо�ьш» (12-19 заданий);
- хвосты «Решения» у Прасолова и подпись автора у Захарова;
- оборванный корень (4 задачи) и 3 фрагмента планиметрии у Захарова.

Каждая находка превращалась в новый фильтр в парсере.

**Ненадёжная проверка.** «Формула рассыпалась на символы» шумит на формате ФИПИ, где буквы и операторы записаны через пробел. Её результаты нужно читать с осторожностью. Не сделана проверка «LLM как судья» (спросить модель, настоящее ли это условие задачи).

## 10. Глоссарий

| термин | значение |
|---|---|
| **dataset (датасет)** | набор размеченных примеров |
| **label (метка)** | правильный ответ для примера (у нас 1 или 0) |
| **позитив / негатив** | пример класса «стереометрия» (1) / «не стереометрия» (0) |
| **hard negative (сложный негатив)** | негативный пример, похожий на позитивный (у нас планиметрия и алгебра) |
| **easy negative (лёгкий негатив)** | негативный пример, который легко отличить (приветствия, болтовня) |
| **source, category** | поля датасета: из какого источника строка и к какому типу относится; в модель не идут |
| **задача на доказательство** | в датасете: текст, где есть корень «докаж» или «обоснуй» |
| **обучающая / тестовая выборка** | данные, по которым модель учится / данные, по которым проверяют её, не показывая заранее |
| **обобщающая способность** | умение модели правильно отвечать на новых примерах |
| **переобучение** | модель запомнила обучающие примеры и хуже работает на новых |
| **утечка данных (leakage)** | в проверку попадает информация, которой у модели быть не должно (например, почти-копия задачи из обучения) |
| **shortcut learning** | модель опирается на лёгкую случайную подсказку (формат записи, стиль), а не на тему |
| **сдвиг априорных вероятностей** | доля классов в реальных данных отличается от доли в датасете |
| **TF-IDF** | способ превратить текст в числа, взвешивая слова по редкости |
| **SVM** | метод опорных векторов: классификатор, который ищет границу с самым широким зазором между классами |
| **LLM** | большая языковая модель |
| **парсинг** | автоматическое чтение страницы или файла и извлечение из него нужных данных |
| **HTML, тег** | язык разметки страниц; тег - метка, по которой видно, где заголовок, где абзац |
| **GET / POST** | два способа запросить страницу: просто «дай» / «дай по этим параметрам» |
| **кодировка** | таблица, по которой байты превращаются в буквы (`windows-1251`, `utf-8`) |
| **TLS-сертификат** | «паспорт» сайта, по которому программа убеждается, что говорит с настоящим сайтом |
| **robots.txt** | файл, в котором сайт сообщает, что роботам читать нельзя |
| **КЭС** | кодификатор элементов содержания: код темы задания у ФИПИ |
| **PDF с текстовым слоем / скан, OCR** | текст в PDF хранится как текст или как картинка; для картинки нужно распознавание текста (OCR) |
| **регулярное выражение (regex)** | язык шаблонов для поиска и замены в тексте |
| **jsonl** | текстовый файл, где одна строка - один JSON-объект |
| **дедупликация** | удаление повторяющихся строк |
| **почти-дубликат** | задача из того же шаблона, отличающаяся числами |
| **перплексия** | насколько языковая модель «удивлена» текстом; у мешанины символов она высокая |
| **зерно (seed)** | число, фиксирующее случайный выбор, чтобы результат повторялся |
