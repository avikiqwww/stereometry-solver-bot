# stereometry-solver-bot

Учебный проект: Telegram-бот для решения задач по стереометрии.
Внутри две ML-модели: **фильтр** («задача / не задача») и **решатель** (LLM).

## Окружение

```bash
uv sync
```

## Сбор данных

Пайплайн из шести шагов, каждый — отдельный скрипт в `parser/`. Данные
складываются в `data/raw/` (сырьё) и `data/processed/` (готовый датасет) —
обе папки не публикуются в репозитории (`.gitignore`), потому что часть
источников защищена copyright. В репозитории только код, который их
воспроизводит.

**1. ФИПИ, ЕГЭ и ОГЭ** — `parser/fipi_parser.py`

```bash
uv run python parser/fipi_parser.py
```

- ЕГЭ, «Математика. Профильный уровень» (`ege.fipi.ru/bank/`): темы КЭС
  7.2–7.4 → `fipi_ege_stereometry.jsonl` (позитив), тема 7.1 →
  `fipi_ege_planimetry.jsonl` (hard negative).
- ОГЭ, «Математика» (`oge.fipi.ru/bank/`): стереометрии в программе 9 класса
  нет вообще, поэтому берём только hard negatives — геометрию (=планиметрия,
  темы 7.1–7.6) → `fipi_oge_planimetry.jsonl` и алгебру (темы 2.x, 3.x) →
  `fipi_oge_algebra.jsonl`.

Технические детали (пагинация, кодировка, сломанный TLS-сертификат сайта,
обоснование легальности) — в докстринге файла.

**2. Прасолов, «Задачи по стереометрии» — основной источник позитива** —
`parser/prasolov_parser.py`

```bash
uv run python parser/prasolov_parser.py путь/к/Стереометрия-Прасолов.pdf
```

Задачника с ФИПИ (123 задачи) не хватает на позитивный класс нужного
размера. PDF книги (найден пользователем, не в репозитории — не публикуем
чужой PDF и не публикуем сырой извлечённый текст, авторское право) содержит
настоящий текстовый слой. Парсер: вырезает страницы раздела «Решения»,
режет оставшееся на отдельные задачи по номерам («2.9.», «3.12.»...),
отбрасывает задачи со ссылкой на рисунок и куски решений, случайно
просочившиеся мимо разбивки по страницам (детектируются по отсутствию
характерных слов условия — «докажите», «найдите» и т.п.) → 586 задач в
`prasolov_stereometry.jsonl`.

**3. Захаров, «Сборник задач по стереометрии для подготовки к ЕГЭ»** —
`parser/zaharov_parser.py`

```bash
uv run python parser/zaharov_parser.py путь/к/077_stereometriya-c2.pdf
```

Ещё один PDF с текстовым слоем (найден пользователем). Задачи в стиле ЕГЭ
типа C2 (координатно-векторный метод), помечены как «Задача N.» — нумерация
повторяется в каждом из 8 уроков книги, поэтому режем по самому маркеру, а
не по сквозному номеру. У книги на каждой странице колонтитул с именем
автора и почтой — иногда он впечатывался прямо в середину задачи на границе
страниц, вырезаем его отдельной регуляркой перед разбиением. → 140 задач
(из 155 найденных маркеров) в `zaharov_stereometry.jsonl`.

**4. SolidGeo (англ. → рус.) — рассмотрен и отклонён**

`parser/solidgeo_translator.py` в сборке **не используется** — код и
объяснение оставлены в репозитории как задокументированный тупик, чтобы
не наступать на те же грабли снова.

[SolidGeo](https://huggingface.co/datasets/SolidGeo/SolidGeo) — англоязычный
датасет из 3113 задач по стереометрии (CC-BY-NC-4.0). Оказался датасетом для
мультимодальных моделей — подавляющее большинство вопросов без картинки не
имеют смысла (числа на рисунке, не в тексте). Первая версия фильтра это
пропускала: после перевода ~60% текстов превращались в обрубки вида
«Найдите длину диагонали» без единого числа. Фильтр ужесточили (требовать
цифру в тексте + отсутствие слов-маркеров рисунка) — самодостаточными из
~3000 оказались только ~130. Даже эти немногие после машинного перевода
звучали недостаточно естественно — решение: не подмешивать SolidGeo вообще,
ни в каком объёме. К тому моменту, как эту находку разобрали, реальных
источников (ФИПИ + Прасолов + Захаров) уже хватило на весь объём позитива
без перевода и даже без синтетики (см. ниже).

**5. Мусор (easy negatives)** — `parser/junk_generator.py`

```bash
uv run python parser/junk_generator.py
```

Реальных датасетов «случайные сообщения боту» не существует — генерируется
по шаблонам (приветствия, болтовня, вопросы не по теме, мета-вопросы о
самом боте) → `junk_easy_negatives.jsonl`.

**6. Сборка финального датасета** — `parser/assemble_dataset.py`

```bash
uv run python parser/assemble_dataset.py
```

Объединяет все источники в пропорции **40% позитив / 40% сложный негатив
(планиметрия + алгебра) / 20% лёгкий негатив**, убирает дубликаты →
`data/processed/filter_dataset.jsonl` (1996 строк, формат `text`, `label`,
`category`, `source`). Позитив: 113 ФИПИ + 559 Прасолов + 128 Захаров —
**весь объём реальными задачами**, ни перевода, ни синтетики не понадобилось.

Есть ещё `parser/stereometry_template_generator.py` — свои параметризованные
шаблоны на случай нехватки объёма реальных данных. Сборка сама подключает
его, только если реальных задач наберётся меньше 800 (сейчас не требуется).

## Проверка качества датасета

Датасет не читается руками целиком — `parser/quality_check.py` прогоняет
автоматические проверки и печатает только подозрительные строки:

```bash
uv run python parser/quality_check.py
```

- Дешёвые эвристики: длина, утечки колонтитулов, оборванные символы (√),
  отсутствие терминов темы/цифр у позитива, почти-дубликаты по шаблону
  (риск утечки данных между train/test при будущем разбиении).
- **Перплексия через локальную языковую модель** (`rugpt3small`, без
  API/ключей) — самый сильный метод здесь: связный русский текст даёт
  низкую перплексию, разваленная формула или обрубок — аномально высокую.
  Именно так нашлась реальная системная проблема: у части заданий ФИПИ
  (multiple-choice с картинкой-вариантом или графиком) текст условия
  извлекался не полностью — оставался обрывок вроде «Решите неравенство»
  без самого неравенства. Масштаб оказался немаленьким: 21% алгебры ОГЭ.
  Исправлено фильтром на отсутствие цифр/знаков в `fipi_parser.py`.

Отчёт — `data/processed/quality_report.txt` (полный, с кириллицей; вывод
в консоль Windows урезан из-за кодировки cp1251).

### Известные ограничения

- В выборке из Прасолова и Захарова остаётся единичный процент шума: PDF —
  сложная вёрстка LaTeX/формул, детекторы страниц-решений и колонтитулов
  ловят почти всё, но не гарантированно 100%.
- Проверка «формула рассыпалась на символы» в `quality_check.py` даёт много
  ложных срабатываний на текстах с ФИПИ — там буквы точек и знаки всегда
  через пробел («A B C D», «26 °»), это формат источника, а не поломка.
  Значению этой конкретной метрики в отчёте доверять не стоит.
- 58 групп почти-дубликатов по шаблону (одна и та же задача, разные числа)
  — не убраны намеренно, это нормальный объём вариативности упражнений,
  но их нужно держать в одной группе при разбиении на train/val/test,
  иначе оценка модели будет завышена (утечка).
