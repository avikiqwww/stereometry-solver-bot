# stereometry-solver-bot

Учебный проект: Telegram-бот, который решает задачи по **стереометрии** (геометрии в пространстве: пирамиды, призмы, шары, сечения).

Бот работает в два шага:

1. **Фильтр.** Пришло сообщение. Это задача по стереометрии или нет?
2. **Решатель.** Если да, задачу решает большая языковая модель (LLM).

В этом репозитории лежит всё, что относится к фильтру: **датасет** и **модели-фильтры**, обученные на нём. Подробная документация - в [docs/](docs/).

## Фильтр

Фильтр - это бинарный классификатор: по тексту сообщения он отвечает `1` (стереометрическая задача) или `0` (не она). Один и тот же датасет используется для разных моделей-фильтров, каждую из них можно сравнить с остальными на одних и тех же данных.

---

## Датасет

Фильтру нужны примеры двух видов: что **является** стереометрической задачей и что **не является**. Причём «не является» должно включать и похожее (планиметрию), иначе модель назовёт стереометрией любую геометрию.

| класс | что это | доля | строк |
|---|---|---|---|
| **1. Позитив** | задачи по стереометрии | 40% | 800 |
| **0. Сложный негатив** | планиметрия и алгебра | 40% | 782 |
| **0. Лёгкий негатив** | приветствия, болтовня, вопросы не по теме | 20% | 400 |
| | | итого | **1982** |

### Источники

| источник | класс | в датасете |
|---|---|---|
| ФИПИ, ЕГЭ (стереометрия) | позитив | 113 |
| Прасолов, «Задачи по стереометрии» | позитив | 560 |
| Захаров, «Сборник задач по стереометрии для ЕГЭ» | позитив | 127 |
| ФИПИ, ЕГЭ (планиметрия) | негатив | 89 |
| ФИПИ, ОГЭ (геометрия) | негатив | 224 |
| Прасолов, «Задачи по планиметрии» | негатив | 149 |
| ФИПИ, ОГЭ (алгебра) | негатив | 320 |
| генератор мусора по шаблонам | лёгкий негатив | 400 |

Сырые данные **не публикуются** (папка `data/` в `.gitignore`): часть источников защищена авторским правом. В репозитории только код, который их воспроизводит.

### Главные решения

- **Сложные негативы нужны.** У планиметрии и стереометрии общие слова («площадь», «угол», «найдите»). Без планиметрии в негативах модель выучила бы только «геометрия - значит стереометрия».
- **Доказательства есть в обоих классах.** Почти все задачи Прасолова начинаются с «Докажите, что…», и модель выучила слово «докажите» как признак стереометрии. Чтобы это убрать, в негативы добавлены все доказательства ФИПИ по планиметрии и 150 доказательств из книги Прасолова по планиметрии. Теперь доказательства составляют **63% позитивов и 61% планиметрических негативов**.
- **Источники сбалансированы в подвыборке.** Прасолов даёт 70% всех позитивов. Для быстрых экспериментов (`tfidf_subset_500.csv`) позитивы берутся поровну из трёх источников.
- **Поле `source` не идёт в модель.** Оно нужно только для контроля (проверки на незнакомом источнике, баланс, поиск утечек).

## Модель: TF-IDF + линейный SVM

**Простыми словами.** Компьютер не умеет читать, ему нужны числа. Поэтому текст приводится в порядок, превращается в набор чисел, а по числам линейный SVM проводит границу между «стереометрией» и «не стереометрией» с самым широким пустым коридором между классами.

```
текст сообщения
   |
   v
предобработка        единая запись вершин, начальные формы слов
   |
   v
TF-IDF               слова -> числа (редкие слова весят больше частых)
   |
   v
линейный SVM         граница между классами
   |
   v
ответ: 1 (стереометрия) или 0 (нет)
```

Результат на всём датасете (5-кратная проверка, данные разбиты по группам почти одинаковых задач, чтобы не было утечки):

| метрика | значение |
|---|---|
| accuracy | 0.967 ± 0.011 |
| precision | 0.960 |
| recall | 0.959 |
| F1 | 0.959 |

Если бы модель всегда отвечала «не стереометрия», accuracy была бы 0.596, поэтому одной accuracy мало. На ЕГЭ-подобных источниках (ФИПИ, Захаров), которых модель не видела при обучении, она находит 99-100% задач.

## Как воспроизвести

**Окружение.**

```bash
uv sync
```

**Сбор данных** (сырьё и PDF лежат в `data/`, в репозиторий не попадают):

```bash
uv run python parser/fipi_parser.py                                   # ФИПИ: ЕГЭ и ОГЭ
uv run python parser/prasolov_parser.py путь/к/prasolov_stereo.pdf    # Прасолов, стереометрия
uv run python parser/zaharov_parser.py путь/к/zaharov.pdf             # Захаров
uv run python parser/prasolov_planimetry_parser.py                    # Прасолов, планиметрия (PDF в data/interim/prasolov_planimetry.pdf)
uv run python parser/junk_generator.py                                # мусор по шаблонам
```

**Сборка и проверка датасета:**

```bash
uv run python parser/assemble_dataset.py     # -> data/processed/filter_dataset.jsonl
uv run python parser/quality_check.py        # отчёт о подозрительных строках (долго, скачивает rugpt3small)
```

**Подвыборка и эксперименты:**

```bash
uv run python -m classifiers.common.prepare_tfidf_data       # подвыборка на 500 строк
uv run python -m classifiers.experiments.tfidf_experiment    # формат записи вершин
uv run python -m classifiers.experiments.morph_experiment    # леммы, слова-указания, проверка на незнакомом источнике
```

Скрипты из `classifiers/` запускаются из корня репозитория как модули (`python -m ...`).

В Windows перед запуском удобно задать `PYTHONIOENCODING=utf-8`, иначе консоль (cp1251) может упасть на символах вроде `√` и `∠`.

## Ограничения

- **Прасолов даёт 70% позитивов**, поэтому на задачах другого стиля (олимпиадные доказательства) качество фильтра заметно ниже.
- **Алгебраических доказательств в негативах нет** (0 из 320).
- **Негативы короче позитивов:** медианы длины 108 (алгебра), 160 (планиметрия) и 171 символ (стереометрия).
- **Формулы из PDF** иногда рассыпаются (дроби, степени); у части задач Прасолова метка стоит «по книге», а не по условию.
- **У ФИПИ у задания может быть несколько тегов темы сразу**, поэтому часть стереометрии попадает ещё и в планиметрию. При сборке такие дубли удаляются (позитивная копия остаётся), но сам парсер этого не исправляет.
- **Реальных сообщений пользователей в данных нет**: опечаток, коротких запросов, строчных обозначений вершин (`abcd`).
- **Доля стереометрии в датасете (40%)** не обязательно совпадает с реальной долей в сообщениях к боту.
