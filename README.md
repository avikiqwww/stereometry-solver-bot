# stereometry-solver-bot

Учебный проект: Telegram-бот, который решает задачи по **стереометрии** (геометрии в пространстве: пирамиды, призмы, шары, сечения).

Бот работает в два шага:

1. **Фильтр.** Пришло сообщение. Это задача по стереометрии или нет?
2. **Решатель.** Если да, задачу решает большая языковая модель (LLM).

В этом репозитории лежит всё, что относится к фильтру: **датасет**, **предобработка текста** и **эксперименты** с TF-IDF и линейным SVM. Подробное объяснение с теорией и разбором кода - в [docs/](docs/).

## Как работает фильтр

**Простыми словами.** Компьютер не умеет читать, ему нужны числа. Поэтому текст сначала приводится в порядок, потом превращается в набор чисел, а уже по числам модель говорит «стереометрия» или «не стереометрия».

```
текст сообщения
   |
   v
[1] предобработка        приводим текст в порядок (вершины, начальные формы слов)
   |
   v
[2] TF-IDF               превращаем слова в числа
   |
   v
[3] линейный SVM         по числам выбираем класс
   |
   v
ответ: 1 (стереометрия) или 0 (нет)
```

**Чуть строже.** Вес слова $t$ в документе $d$ считается по формуле TF-IDF:

$$
w_{t,d} = \mathrm{tf}(t, d) \cdot \left( \ln\frac{1 + N}{1 + \mathrm{df}(t)} + 1 \right),
$$

где $N$ - число документов, $\mathrm{df}(t)$ - в скольких из них встречается слово $t$. Частые слова («найдите») получают маленький вес, редкие и характерные («пирамиды») получают большой. Потом вектор документа нормируется на свою длину. Классификатор - линейный SVM: он ищет плоскость, которая разделяет классы с самым широким пустым коридором.

## Датасет

Фильтру нужны примеры двух видов: что **является** стереометрической задачей и что **не является**. Причём «не является» должно включать и похожее (планиметрию), иначе модель назовёт стереометрией любую геометрию.

| класс | что это | доля | строк |
|---|---|---|---|
| **1. Позитив** | задачи по стереометрии | 40% | 800 |
| **0. Сложный негатив** | планиметрия и алгебра | 40% | 782 |
| **0. Лёгкий негатив** | приветствия, болтовня, вопросы не по теме | 20% | 400 |
| | | итого | **1982** |

### Источники

| источник | класс | в датасете |
|---|---|---|
| ФИПИ, ЕГЭ (стереометрия) | позитив | 113 |
| Прасолов, «Задачи по стереометрии» | позитив | 560 |
| Захаров, «Сборник задач по стереометрии для ЕГЭ» | позитив | 127 |
| ФИПИ, ЕГЭ (планиметрия) | негатив | 89 |
| ФИПИ, ОГЭ (геометрия) | негатив | 224 |
| Прасолов, «Задачи по планиметрии» | негатив | 149 |
| ФИПИ, ОГЭ (алгебра) | негатив | 320 |
| генератор мусора по шаблонам | лёгкий негатив | 400 |

Сырые данные **не публикуются** (папка `data/` в `.gitignore`): часть источников защищена авторским правом. В репозитории только код, который их воспроизводит.

### Главные решения

- **Сложные негативы нужны.** У планиметрии и стереометрии общие слова («площадь», «угол», «найдите»). Без планиметрии в негативах модель выучила бы только «геометрия - значит стереометрия».
- **Доказательства есть в обоих классах.** Почти все задачи Прасолова начинаются с «Докажите, что…», и модель выучила слово «докажите» как признак стереометрии. Чтобы это убрать, в негативы добавлены все доказательства ФИПИ по планиметрии и 150 доказательств из книги Прасолова по планиметрии. Теперь доказательства составляют **63% позитивов и 61% планиметрических негативов**.
- **Источники сбалансированы в подвыборке.** Прасолов даёт 70% всех позитивов. Для быстрых экспериментов (`tfidf_subset_500.csv`) позитивы берутся поровну из трёх источников.
- **Поле `source` не идёт в модель.** Оно нужно только для контроля (проверки на незнакомом источнике, баланс, поиск утечек).

## Предобработка текста

Задача предобработки - сделать так, чтобы модель училась **теме** задачи, а не оформлению. Любое различие в оформлении, которое совпадает с классом (способ записи вершин, стиль формулировок), модель может использовать как подсказку вместо темы.

| шаг | что делает | зачем |
|---|---|---|
| **1. Вершины** | `A B C D`, `ABCD`, `A1B1C1D1` превращаются в токены `точки4`, `точки_инд` и т. д. | у ФИПИ вершины записаны через пробел, у книг слитно; по записи можно угадать источник и класс |
| **2. Леммы** | «треугольника», «треугольнике» -> «треугольник» | вес слова не размазывается по падежам (`pymorphy3`) |
| **3. Слова-указания** | убираются «докажите», «найдите», «вычислите», «пусть», «что», «если» | эти слова отражают стиль источника, а не тему |

Пример: «Дан куб A B C D A 1 B 1 C 1 D 1 . Докажите, что диагональ AC1 перпендикулярна плоскости A1BD» превращается в слова `дать`, `куб`, `точки_инд`, `диагональ`, `точки_инд`, `перпендикулярный`, `плоскость`, `точки_инд`.

Проверка показала, зачем нужен шаг 1: если переписать планиметрические задачи в слитную запись вершин, без нормализации ложных срабатываний становится в 6 раз больше (1.0% -> 6.4%), а с нормализацией остаётся 1.4%.

## Результаты

Линейный SVM здесь - **измерительный инструмент**: по тому, где он ошибается, видно проблемы данных и предобработки. Пять вариантов предобработки сравнивались на полном датасете (1982 строки):

| вариант | accuracy | F1 | ROC-AUC |
|---|---|---|---|
| 1. без предобработки | 0.969 ± 0.007 | 0.962 | 0.995 |
| 2. + вершины | 0.965 ± 0.008 | 0.957 | 0.993 |
| 3. + стемминг | 0.970 ± 0.010 | 0.963 | 0.996 |
| 4. + леммы | 0.968 ± 0.013 | 0.960 | 0.996 |
| **5. + леммы, без слов-указаний** | 0.967 ± 0.011 | 0.959 | 0.995 |

Разброс «±» - это разброс между пятью фолдами кросс-валидации. Все варианты внутри него, поэтому на перемешанных данных они не различаются. Различие видно на втором тесте: **модель обучается без одного источника, и смотрим, сколько его задач она находит** (recall):

| отложенный источник | вариант 1 | вариант 5 |
|---|---|---|
| ФИПИ, ЕГЭ | 1.00 | 0.99 |
| Захаров | 0.98 | 1.00 |
| Прасолов | 0.07 | 0.26 |

Матрица ошибок рабочего варианта (каждый документ предсказан моделью, которая его не видела):

|  | модель: «стерео» | модель: «не стерео» |
|---|---|---|
| на самом деле стерео | 767 | 33 |
| на самом деле нет | 32 | 1150 |

Отсюда: accuracy $= \frac{767 + 1150}{1982} = 0.967$, precision $= 0.960$, recall $= 0.959$. Если бы модель всегда отвечала «не стереометрия», accuracy была бы 0.596, поэтому одной accuracy мало.

**Как читать.** Результат 0.967 честнее прежних 0.98: часть лёгких подсказок (формат вершин, слово «докажите») убрана. На ЕГЭ-подобных источниках фильтр находит 99-100% задач, на олимпиадных доказательствах Прасолова только 26%.

## Как воспроизвести

**Окружение.**

```bash
uv sync
```

**Сбор данных** (сырьё и PDF лежат в `data/`, в репозиторий не попадают):

```bash
uv run python parser/fipi_parser.py                                   # ФИПИ: ЕГЭ и ОГЭ
uv run python parser/prasolov_parser.py путь/к/prasolov_stereo.pdf    # Прасолов, стереометрия
uv run python parser/zaharov_parser.py путь/к/zaharov.pdf             # Захаров
uv run python parser/prasolov_planimetry_parser.py                    # Прасолов, планиметрия (PDF в data/interim/prasolov_planimetry.pdf)
uv run python parser/junk_generator.py                                # мусор по шаблонам
```

**Сборка и проверка датасета:**

```bash
uv run python parser/assemble_dataset.py     # -> data/processed/filter_dataset.jsonl
uv run python parser/quality_check.py        # отчёт о подозрительных строках (долго, скачивает rugpt3small)
```

**Подвыборка и эксперименты:**

```bash
uv run python classifiers/prepare_tfidf_data.py   # подвыборка на 500 строк
uv run python classifiers/tfidf_experiment.py     # формат записи вершин
uv run python classifiers/morph_experiment.py     # леммы, слова-указания, проверка на незнакомом источнике
```

В Windows перед запуском удобно задать `PYTHONIOENCODING=utf-8`, иначе консоль (cp1251) может упасть на символах вроде `√` и `∠`.

## Ограничения

- **Прасолов даёт 70% позитивов**, поэтому на задачах другого стиля (олимпиадные доказательства) качество низкое: recall 0.26.
- **Алгебраических доказательств в негативах нет** (0 из 320). Слово «докажите» из признаков убрано, но данных всё равно нет.
- **Негативы короче позитивов:** медианы длины 108 (алгебра), 160 (планиметрия) и 171 символ (стереометрия).
- **Формулы из PDF** иногда рассыпаются (дроби, степени); у части задач Прасолова метка стоит «по книге», а не по условию.
- **У ФИПИ у задания может быть несколько тегов темы сразу**, поэтому часть стереометрии попадает ещё и в планиметрию. При сборке такие дубли удаляются (позитивная копия остаётся), но сам парсер этого не исправляет.
- **Реальных сообщений пользователей в данных нет**: опечаток, коротких запросов, строчных обозначений вершин (`abcd`).
- **Доля стереометрии в датасете (40%)** не обязательно совпадает с реальной долей в сообщениях к боту.
